# AGENTS.md

libGDX game **"The Grue"** (package / Play id `timboe.hunted`), desktop + Android. There are **no tests**; verification is compilation and running.

## Commands

- `.\gradlew.bat :lwjgl3:run` — run desktop; working dir is root `assets/`
- `.\gradlew.bat :core:compileJava` — fastest sanity check of game logic
- `.\gradlew.bat :android:assembleDebug` — build APK
- `.\gradlew.bat :android:run` — custom task: installs + launches via adb on a device/emulator
- `.\gradlew.bat :lwjgl3:jar` — runnable fat jar `TheGrue-{projectVersion}.jar`

Environment:
- Gradle 8.14.3 wrapper needs **Java 17** to run (foojay auto-provisioning is configured); code itself compiles to Java 11 (`--release 11`).
- Android builds need `local.properties` with `sdk.dir` or `ANDROID_SDK_ROOT`; `local.properties` is gitignored.
- `gradle.properties` sets `org.gradle.daemon=false` and `quiet` logging: every invocation is a cold start, expect slowness and minimal output.

## Architecture

- `core/` holds **all** game logic under `timboe.hunted.*`: `screen/` (GameScreen, EntryScreen, LooseScreen), `entity/`, `world/` (procedural `WorldGen`), `manager/`, `pathfinding/`.
- `lwjgl3/` and `android/` contain only the platform launchers (`Lwjgl3Launcher`, `AndroidLauncher`).
- Entry point: `HuntedGame.create()` boots the singletons (Textures, Sprites, Physics, Sounds, WorldGen, GameState).

## Naming trap

The product is **"The Grue"** (`appName`, window title, jar name), but all Java packages are `timboe.hunted`, Android `namespace` is `com.timboe.hunted`, `applicationId` is `timboe.hunted`. Preserve the historical package; do not "fix" it.

## Quirks

- `assets/assets.txt` is regenerated by the `generateAssetList` task during `processResources` (root `build.gradle`). Never hand-edit it.
- Game textures come from one packed atlas (`assets/sprites.txt` + `sprites.png`); source art/audio lives under `assetCreation/` with texture-packer settings in `assetCreation/texturePacker.tps`. Regenerate the atlas when adding tiles, never commit loose sprite sheets into `assets/`.
- Debug rendering (`Box2DDebugRenderer`, stage debug) is gated on the static `HuntedGame.debug` field in `HuntedGame.java`. It and the other `HuntedGame` toggles (`lights`, `floodlight`, `zoomOut`, `fps`, etc.) are compile-time booleans only — there are no runtime key toggles.
- Release artifacts (`.aab`, `.apk`, `.jar`) are deliberately committed at the repo root.
